## 0. 现状与目标

| 指标 | 上一轮 | 验收线 | 差距 |
|---|---|---|---|
| 最终答案正确率 | 92.2%（107/116） | ≥ 92% | ✅ 刚压线 |
| **错答率** | **6.9%（8/116）** | **≤ 3%** | ❌ **唯一阻塞项** |

目标只有一句话：**在独立测试集上，答案正确率保持 ≥92%，错答率降到 ≤3%。**

「错答」= 提交了一个错误的答案（消耗登录尝试、可能触发风控）；
「换图」= 返回空串让程序重新取图（安全）。本项目的原则是**宁可换图，不能错答**。

## 1. 先泼冷水：以下方案已实测证伪，不要再试

### 1.1 置信度阈值 —— **证伪，别做了**

Windows 侧写了 `ml/scripts/conf_threshold.py`，在 116 张独立测试集上扫了
min / mean / seq 三种口径 × 0.10~0.99 全区间阈值：

| 错答样本 | 真值 → 识别 | min 置信度 |
|---|---|---|
| cap_0027 | `61加6` → `6加6` | **1.000** |
| cap_0094 | `31加6` → `3加6` | 0.999 |
| cap_0055 | `22加1` → `2加1` | 0.999 |
| cap_0016 | `22除2` → `12除2` | 0.969 |
| cap_0080 | `93加7` → `9加7` | 0.917 |
| cap_0009 | `2乘1` → `2乘7` | 0.888 |
| cap_0069 | `5乘7` → `1乘7` | 0.536 |
| cap_0040 | `75减7` → `15减7` | 0.502 |

- **8 个错答里 5 个置信度 ≥0.888，4 个接近满分。** 模型对自己的错误零怀疑。
- 正确样本 min 置信度 p1=0.534 → 阈值 0.54 时错答仍有 5.2%，正确率已掉到 89.7%。
- 阈值开到 0.99：错答剩 6.3%，正确率只剩 51.7%。**不存在能用的切点。**
- `mean` / `seq` 口径在 0.10~0.61 完全无区分度。

根因：这些错误是**"看不见字边界"**（两个 `2` 粘连，模型只看到一段连续的 2 特征），
不是"看见了但不确定"。没有犹豫信号，阈值天然救不了。
`conf_threshold.py` 保留在 scripts/ 里，换模型后可重跑复核，但别指望它达标。

### 1.2 "错误集中在两位数 A 的首位" —— 归因不准，别按这个补数据

Windows 侧写了 `ml/scripts/error_profile.py`，双口径统计：

| 维度 | 独立测试集(116) | 训练留出集(460) | 判断 |
|---|---|---|---|
| 含 `1` 或 `7` | **11.7%** vs 1.8% | **19.0%** vs 12.5% | ✅ 唯一双口径一致 |
| A 两位 vs 一位 | 8.8% vs 4.2% | 11.6% vs **20.3%** | ❌ 留出集上反了 |
| B 两位 vs 一位 | 0% vs 8.3% | 24.4% vs 13.6% | ❌ 矛盾 |
| 运算符最高 | 加 12.9% | 减 20.3% | ❌ 矛盾 |

8 个错答的真实结构：**4 个相邻两位合并**（`22加1→2加1`、`31加6→3加6`、
`61加6→6加6`、`93加7→9加7`）+ **4 个细笔画误读**（`5→1`、`7→1`、`2→1`、`1→7`）。
**运算符一个都没错。** 真正稳的信号：**细笔画数字 `1`/`7`（错答率差 6.5 倍）**。

另：留出集错答率 15.4% 远高于测试集 6.9%，两者不同批次，留出集可能有标签噪声残留，
定位错误结构请以独立测试集为准。

## 2. 本轮任务（按此顺序做）

### 任务 1：换 83.5% 权重重新导出（10 分钟，先做这个）

上一轮导出的 `crnn_math.onnx` 用的是 82.6% 的 `crnn_math.pt`，
而 **`crnn_math_ep234_83.5.pt` 从没被导出过**：

```bash
python ml/scripts/export_onnx.py --ckpt ml/models/crnn_math_ep234_83.5.pt \
    --out ml/models/crnn_math_835.onnx
python ml/scripts/evaluate.py --raw ml/dataset/test_raw \
    --labels ml/dataset/test_labels.csv --onnx ml/models/crnn_math_835.onnx
python ml/scripts/error_profile.py --onnx ml/models/crnn_math_835.onnx
```

**不要覆盖现有 `crnn_math.onnx`**，文件名带 `835`，两边数字都报出来再决定用哪个。

### 任务 2：定向补数据 —— 细笔画字符专项

错答集中在含 `1`/`7` 的样本。目标：**把含 `1` 或 `7` 的训练样本占比提上去**，
并保证 `1`/`7` 出现在 A 首位、A 次位、B 位三种位置上的量大致均衡
（不要只堆在某一格）。

1. 补采：沿用 `HANDOFF_补采与标注任务.md` 的流程与规矩
   （`--skip` 接现有最大编号、0.25s 间隔、标注只转录所见、`?` 弃标）。
   建议补 **800~1200 张**。
2. **不要**按"结果应该整除/非负"去筛或修标注 —— 见 AGENT_BRIEF §1，
   `55减23`、`1减8`、`2除7` 都是真实存在的题。
3. 标注质量控制沿用上一轮的做法：双人独立标注 → 只裁定分歧项 → 全量校对。
   首轮 AI 标注噪声率实测 4.5%~14.7%，**这一步的质量比训练技巧重要**。
4. 补完后重新跑 `error_profile.py`，确认 `1`/`7` 组的错答率下降。

### 任务 3：增强升级 —— 细笔画鲁棒性

现有 `_augment()`（train_crnn.py）已有平移/旋转/穿字斜线/噪声/擦除。
在它基础上**加两项**（都在 `train_crnn.py`，别动 `common.py` 的预处理契约）：

1. **笔画粗细抖动**：以 0.3 概率对字符区域做 1px 腐蚀（模拟 `1`/`7` 被干扰线吃细）
   或 1px 膨胀（模拟粗体）。实现上用 `scipy.ndimage` 或纯 numpy 的 3x3 邻域
   min/max 滤波即可，作用在整图上就行（背景是白的不受影响）。
2. **含 `1`/`7` 样本过采样**：`CaptchaDataset` 里给含 `1`/`7` 的样本 2 倍采样权重
   （用 `torch.utils.data.WeightedRandomSampler`，或最简单地在样本列表里复制一份）。
   过采样要配合增强使用，否则只是背下来。

**训练与对比口径**：换任何超参/增强，都必须在 116 张独立测试集上报
「答案正确率 + 错答率 + 错误清单」，并跑 `error_profile.py` 确认 `1`/`7` 组改善。

### 任务 4：输入分辨率实验（可选，收益不确定，放在最后）

现状：原图 200×60 压到 32×200，字符高约 16px，细笔画 `1` 容易糊。
提分辨率可能有效，但**牵一发动全身**，放最后做：

- `IMG_H=64` 时 CNN 的高度池化链是 /2×5，64/32=2 落不到 1，
  **必须同步改池化结构**（例如把最后一次 `MaxPool(2,1)` 改成 `(2,2)`），
  保证输出高度恰好为 1、宽度方向时间步数随意（T 变大没问题）。
- `IMG_W` 不用动（200 已经够宽，加大只增计算量）。
- 改了 `common.py` 的 `IMG_H` 后，**所有已训练模型全部作废，必须重训**；
  `selftest.py` 也要跑一遍确认预处理自洽。
- 若试了没有明显收益（±1 个点以内），回滚到 32，在报告里写一句结论即可。

### 任务 5：扩充独立测试集（300~500 张，盲标）

116 张的 95% 置信区间约 ±5 个点，92.2% 属于"刚好压线"。本轮结束时要给出
**更可信的数字**：

1. 新采 **300~500 张**，**不要**先跑模型看输出。
2. 完全盲标（不看任何模型输出；上一轮的测试集是看着模型输出裁定的，有乐观偏差）。
3. 标完后先固定标签，再一次性评估新旧两个模型，报告里给置信区间
   （`正态近似或 Wilson 区间`均可）。
