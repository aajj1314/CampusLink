# 给接手者（AI Agent / 新同事）的交接说明

> **状态：模型已训练完成，ONNX 已导出，独立测试集已评估。**
> 本文档讲清楚：这件事为什么做、做到什么程度、还差什么、以及上一轮踩过哪些坑。
> 使用方法看 [`README.md`](README.md)；本文档只讲背景、结论和经验。

---

## 0. 一句话现状

门户登录验证码从「4 位字符」改成了「算术题」，原通用 OCR 只有 13% 正确率。
本目录用 CRNN + CTC 训练了专用模型，**在 116 张完全独立的测试集上达到
最终答案正确 92.2%、错答率 6.9%**。

- 答案正确率 ≥ 92%：**已达标**
- 错答率 ≤ 3%：**未达标**（唯一遗留项，解法见第 6 节）

**范围**：只做「图片 → 算式文本」（如 `7加9`）。把 `7加9` 算成 `16` 不是本目录的活，
那部分在 `campuslink/core/captcha_math.py` 里，已实现。

**接线不在本任务范围内**：模型怎么接进 Windows 客户端由用户另行决定。
不要改 `campuslink/` 运行时代码。

## 1. 这个验证码为什么难

格式固定为 `A <运算符> B = ?`，200×60 PNG，来自 `http://10.6.6.6/ACaptcha.ashx`。

- 主字符颜色随机（深青 / 深蓝 / 深绿 / 深紫 / 灰，HSV 跨度极大）
- 字符随机倾斜，同一行互相压边
- **深色细斜线直接穿过字符** —— 任何去线算法都会连带伤到笔画
- 还有细笔画小字干扰（偏小/上标数字、浅色背景数字串、鲜艳斜字）

**实测数据规律（与旧文档不符，以此为准）**：

- A：1~2 位，可到 98
- B：**多数 1 位，但减法常见 2 位**（如 `55减23`）
- **结果可为负、可不整除**：`1减8=?`、`2除7=?` 都真实存在
- 运算符：`加`/`乘` 是画在图上的**汉字**；`÷` 是"一横 + 上下两点"；`−` 是单横线

> 旧的交接文档写"B 恒为 1 位"、"结果必然非负/整除"，**这是错的**。
> 按错误规律反推修正标注，曾造成一批系统性错标，务必避免。

## 2. 已验证无效的方案（不要再试）

| 方案 | 为什么不行 |
|---|---|
| Hough 直线检测去干扰线 | Canny 把字符笔画也当直线，抹完 `28÷4=?` 的 `4` 就没了 |
| 形态学开运算 + 笔画宽度过滤 | 数字能保住，但**汉字 `乘`/`加` 的细笔画被一起削掉** |
| 中值滤波（3×3 / 5×5） | 改善有限，字符重叠导致的粘连依旧 |
| 用 `=` 的几何特征做锚点 | 30 张里 0 张检出 |
| ddddocr `det=True` 目标检测 | 那是给滑块点选设计的，框数和位置都不对 |
| 整行识别 + 正则后处理 | 70% 能解出式子，但尾部 `?` 混进操作数，答案几乎全错 |
| AntiCAP 的 `CRNN_Math.onnx` | 字符集里**没有汉字**，实测 10 张全错 |

**结论**：只能拿本门户真实样本，按 CRNN + CTC 重新训练。

## 3. 最终结果

| 项目 | 数值 |
|---|---|
| 训练图 / 有效标注 | 3164 张 / 3071 条 |
| 独立测试图 / 标注 | 120 张 / 116 条（4 张模糊弃标） |
| 测试集最终答案正确 | **92.2%**（107/116） |
| 错答率 | **6.9%**（8/116） |
| 空输出（安全换图） | 0.9%（1/116） |
| 训练时 val_exact | 83.5%（461 张留出集） |
| 模型体积 | 21.2 MB（ONNX） |
| 训练耗时 | 约 2s/轮（RTX 4060 Laptop） |

**错误结构**：8 个错答**全部是操作数数字错，运算符一个都没错**，且正好分两类各占一半：

- **相邻两位被合并成一位**（4 个）：`22加1`→`2加1`、`31加6`→`3加6`、
  `61加6`→`6加6`、`93加7`→`9加7`
- **细笔画数字误读**（4 个）：`5`→`1`、`7`→`1`、`2`→`1`、`1`→`7`

共同点：全部集中在含 `1`/`7` 的样本上（见 6.2 的双口径统计）。

## 4. 上一轮踩过的坑（**照着避**）

### 4.1 采样会覆盖旧图
`tools/captcha_sampler.py` 从 `cap_0000` 开始编号。往已有目录补采**必须**传
`--skip <现有最大编号+1>`，否则直接覆盖旧图。本轮就发生过一次，靠 `dataset.zip` 恢复。

### 4.2 依赖版本
- `torch 2.2.1+cu121` 与 `numpy 2.x` **不兼容**（`RuntimeError: Numpy is not available`），
  必须 `numpy<2`（实测 1.26.4）。
- 装 `onnx` 会把 numpy 拉回 2.x，装完要再固定一次。
- 系统没装 `python3-venv` 时：`python3 -m venv --without-pip` + get-pip.py 引导。

### 4.3 评估口径会骗人
`evaluate.py` 默认评估**全部已标注图**，其中大部分参与过训练，分数虚高 5~7 个点
（实测全量 87.2% vs 独立测试集 80.2%）。
**只看 `--holdout` 或独立测试集。**

### 4.4 通用 OCR 思路不适用，但"数据增强"极其有效
初版增强只有亮度/对比度，模型把训练集背下来（train loss 0.0005）而验证集仅 5%。
加上平移、±4° 旋转、合成穿字斜线、高斯噪声、随机擦除后，同样数据 **5% → 80%**。

### 4.5 CTC 有"全 blank 平台期"
`ReduceLROnPlateau` 默认 patience=4 会在平台期把 lr 砍到 1/8，模型再也逃不出来。
必须 `--sched-patience 30` 左右。

### 4.6 跑满轮次没用
lr 降到 2e-4 以下后验证集不再提升，train loss 继续掉纯属过拟合。
实测早停结果（83.5%）**优于**跑满 300 轮（82.6%）。

### 4.7 标注噪声是小样本训练的最大杀手
新批次首轮 AI 标注噪声率实测 **4.5%~14.7%**，还出现过**标注串行错位**
（cap_2592 拿到了 cap_2593 的标签）。这类错误对训练毒害远大于调参收益。
有效做法：**双人独立标注 → 只人工裁定分歧项 → 再全量校对一遍**。

### 4.8 汉字 `加` 最容易错
小尺寸下"口"像 0/8、"力"像除号偏旁：`5加3` 被标成 `5除3`、`28除4` 被标成 `2加4`。
校对时这类错误占比最高。

### 4.9 图片上传/读取偶发失败
若用带视觉能力的 Agent 批量读图，会出现 `Upload failed` 或批次错位。
缓解：**先转成 RGB JPEG（放大到 400×120）再读**，一次读一张，失败重试 ≤3 次，
并删掉失败样本或保留原标注。

## 5. 硬约束（**不要做的事**）

1. **不要改 `ml/scripts/common.py` 里的 `CHARS`**。
   字符集 `0123456789加减乘除` 是 12 类，`campuslink/core/captcha_math.py` 按它解析。
2. **不要改预处理尺寸**（`IMG_H=32`、`IMG_W=200`）。
3. **训练标签不要带 `=?`**。尾部固定标记交给 CTC 当空白忽略。
4. **不要在模型输出上做 `max_b_digits` 截断**。模型输出的是干净 `A<op>B`，
   两位 B 是真实的，截断会算错。
5. **不要动 `campuslink/`**。那是运行时代码，有 223 条测试盯着。
6. **不要把 `ml/dataset/` 或 `ml/models/` 提交到 git**，也不要上传到公共位置。
7. **不要用"结果应非负/整除/B 应一位"去反推或修正标注** —— 已验证是错的规律。

**合规红线**：只服务单一账号、不做多账号池、不规避门户并发/频率限制、
不伪造 MAC、不逆向验证码生成算法。做的是"让 OCR 认得更准"的正当工程问题。

## 6. 还差什么（唯一遗留项）

**错答率 6.9% > 验收线 3%。**

### 6.1 「加置信度阈值」这条路已实测走不通（2026-10-19 复盘）

原建议是"把低于阈值的输出改判空串，让错答变成换图"。
在 116 张独立测试集上实测（`ml/scripts/conf_threshold.py`），**行不通**：

| 错答样本 | 真值 | 识别 | min | mean | seq |
|---|---|---|---|---|---|
| cap_0027 | 61加6 | 6加6 | 1.000 | 1.000 | 1.000 |
| cap_0094 | 31加6 | 3加6 | 0.999 | 0.999 | 0.999 |
| cap_0055 | 22加1 | 2加1 | 0.999 | 1.000 | 1.000 |
| cap_0016 | 22除2 | 12除2 | 0.969 | 0.992 | 0.992 |
| cap_0080 | 93加7 | 9加7 | 0.917 | 0.972 | 0.971 |
| cap_0009 | 2乘1 | 2乘7 | 0.888 | 0.963 | 0.961 |
| cap_0069 | 5乘7 | 1乘7 | 0.536 | 0.845 | 0.812 |
| cap_0040 | 75减7 | 15减7 | 0.502 | 0.750 | 0.709 |

正确样本的 min 置信度分位：**p1=0.534 / p5=0.661 / p10=0.777 / p50=0.993**。

- **8 个错答里 5 个置信度 ≥0.888，其中 4 个接近 1.000。**
- 模型不是"拿不准"，而是**确信自己看对了**。
- 阈值只会砍掉低置信度的**正确**样本：0.54 时正确率 92.2%→89.7%，
  错答仍有 5.2%；一路开到 0.99，错答还剩 6.3%，正确率只剩 51.7%。
- `mean` / `seq` 两个口径在 0.10~0.61 区间**完全没有区分度**（错答率纹丝不动）。

**根因**：错误是"看不见字边界"，不是"看见了但不确定"。
看图可知 `cap_0055` 的 `22` 两个 2 是粘连的，模型只看到一段连续的 2 特征；
`cap_0094` 的 `1` 被干扰线压住了。这类错误没有任何"犹豫"信号可以用阈值捞出来。

### 6.2 错误结构：原归因要弱化

`ml/scripts/error_profile.py` 按四个维度切开统计：

| 维度 | 独立测试集（116） | 训练留出集（460） | 判断 |
|---|---|---|---|
| 含 `1` 或 `7` | **11.7%** vs 1.8% | **19.0%** vs 12.5% | 两口径方向一致：**细笔画字符是主要错误源** |
| A 两位 vs 一位 | 8.8% vs 4.2% | 11.6% vs **20.3%** | **矛盾** |
| B 两位 vs 一位 | 0%（20 张全对） | 24.4%（78 张） | **矛盾** |
| 运算符最高 | 加 12.9% | 减 20.3% | **矛盾** |

**所以原文写的"错误高度集中在两位数 A 的首位被漏掉"要弱化**：
116 张上成立，460 张上不成立（A 一位反而更差）。
唯一在两个口径下都稳的信号是 **`1`/`7` 这类细笔画数字**。

另注意：留出集整体错答率 15.4%，远高于测试集 6.9%，两者来自不同批次，
**留出集可能仍有标签噪声**（见 4.7）。定位错误结构请以独立测试集为主。

### 6.3 下一步（按收益排序）

1. **先换 83.5% 那个权重**（零成本，只是重新导出）
   现在的 `crnn_math.onnx` 是从 82.6% 的 `crnn_math.pt` 导出的，
   而 `crnn_math_ep234_83.5.pt` 的 val_exact 更高：
   ```bash
   python ml/scripts/export_onnx.py --ckpt ml/models/crnn_math_ep234_83.5.pt
   python ml/scripts/evaluate.py --raw ml/dataset/test_raw --labels ml/dataset/test_labels.csv
   ```
2. **针对细笔画数字补数据 / 加增强**
   定向补采含 `1`/`7` 的样本；增强里加"细笔画加粗/变细"、"局部遮挡"。
3. **提高输入高度**（改动大，需重训）
   原图 200×60 压到 32×200 后字符高约 16px，细笔画 `1` 容易糊。
   试 `IMG_H=48/64` —— 但这要同时改 `common.py` 与推理侧，属于重训任务。
4. ~~加置信度阈值~~ —— **已实测证伪，见 6.1，不要再试。**
