# 交接文档：验证码补采 + 视觉标注（外包任务）

> 你（AI Agent）的任务只有两件事：**采样新验证码图片** 和 **给图片做视觉标注**。
> 不需要训练模型、不需要导出、不需要碰任务范围外的任何文件。
> 请完整读一遍再动手，标注规则一节尤其重要 —— 历史上多个 AI 在同一处栽过跟头。

---

## 0. 你拿到什么、要交付什么

你手上这个 `dataset/` 文件夹可能是一份拷贝。**你的所有操作只发生在这个文件夹内部**，
不要读写文件夹之外的任何路径（包括系统 /tmp —— 会被清空，历史教训）。

| 项 | 说明 |
|---|---|
| `raw/` | 已有 **1564 张**验证码图（`cap_0000.png` ~ `cap_1563.png`，200×60 PNG）。**一律不许改动、不许覆盖** |
| `labels.csv` / `labels_auto.csv` | 已有标注，**不许改动**（你的结果写进新文件） |
| `sampler.py` | 给你的采样脚本（纯标准库），用法见下 |
| `tmp/` | **由你创建**，放你的中间文件（分片 CSV、清单等）。完工时留着即可，用户会统一清理 |

**交付物（做完后文件夹里应该多出这些）**：
1. `raw/` 里新增约 **1600 张**新图，编号从 **`cap_1564.png` 连续往后**（先扫描确认现有最大编号，不要硬编码 —— 历史上发生过编号从 0 重来覆盖旧图的事故）
2. `labels/labels_new.csv` —— **只含新图**的标注，两列 `filename,label`，UTF-8 **无 BOM**、LF 换行、首行 `filename,label`
3. 一份简短报告（对话里说出即可）：实际采样数/失败数、标注总数、`?` 数量、加/减/乘/除分布

**不要做**：改 `labels.csv`、改 `labels_auto.csv`、动旧图、训练模型、碰 `campuslink/`、把图片上传到任何外部位置。

## 1. 第一步：采样（需要能访问校园网门户）

先测网络：

```bash
curl -s -m 5 -o /dev/null -w "%{http_code}" http://10.6.6.6/ACaptcha.ashx
```

- 返回 `200` → 继续开工
- 超时/失败 → **停下来报告"网络不通"**，等用户切换网络。不要伪造数据、不要跳过采样直接标注旧图

网络通后执行（注意 `--skip` 必须等于现有最大编号 + 1）：

```bash
python3 sampler.py --count 1600 --skip 1564 --out raw --interval 0.25
```

- 间隔别低于 0.25s，别打崩门户（这是真实的高校认证服务，只做温和采集）
- 脚本会校验 PNG magic bytes，失败/重复会跳过并计数
- 采完核对：`ls raw | wc -l` 应约为 1564 + 1600 = 3164 左右

**合规红线（不要越过）**：单账号场景的正当训练素材采集；不伪造 MAC、不逆向验证码生成算法、
不高频压测门户、图片不上传外部。

## 2. 第二步：视觉标注（核心工作，质量决定一切）

用你的**视觉能力**（逐张读图）给每张新图标注算式。图的样式：
`A<运算符>B=?`，例如 `7加9=?`、`28÷4=?`、`57-0=?`、`55-23=?`。

### 标注规则（已用实图逐条验证过的最终版，严格执行）

1. 标注格式 `A<运算符>B`，**不带 `=?`**
2. 运算符统一用汉字：
   - 图上是汉字 `加` → `加`；汉字 `乘` → `乘`
   - 图上是符号 `÷`（一横上下两点）→ `除`
   - 图上是符号 `−`（单横线）→ `减`
3. **减法的 B 经常是两位数**（这是历史上最多 AI 犯错的地方）。
   铁证样例就在 `raw/` 里，动手前先看这四张校准：
   - `cap_0015.png` = `1减8`
   - `cap_0017.png` = `55减23`（减号后两个实心同尺寸同基线数字 → B 取两位）
   - `cap_0027.png` = `41减22`
   - `cap_0113.png` = `8除9`
4. **门户随机出题，结果可为负、可不整除**：`1减8`、`2除7` 都是真实存在的题。
   **绝对不要用"结果应该是多少"（整除、非负）来反推或"修正"识别结果**，
   只按图上实心主字符转录。历史上正是这个"反推"毁掉过一批标注
5. 忽略干扰元素（它们是刻意加的）：
   - 明显偏小 / 上标样式的数字（如 `5²` 里的 2）
   - 倾斜角度明显更大、颜色鲜艳、笔画纤细的字符
   - 背景浅色数字串（如淡灰色的 `0123456778`）
   - 穿过字符的深色细斜线
6. **拿不准 → 标 `?`**。错标注比少标注伤害大得多
   （`除` 认成 `减`，答案 7 变 24，是灾难性错误）

### 工作方式建议

- 逐张 Read 读图，每批 ~260 张；如果条件允许，用多个并行子代理分片，
  每片写自己的中间 CSV 到 `tmp/`，最后合并
- 全部标完后**做一遍自查**：抽查 20 张重新读图核对；统计四则运算符分布，
  正常应大致均衡（各 22%~28%）。某类特别少说明你系统性误判
- 已有数据的参考分布：加 24%、减 27%、乘 23%、除 26%（可作合理性对照）
- 速度不设限，**准确性优先**

### 输出

`labels/labels_new.csv`：

```
filename,label
cap_1564.png,7加9
cap_1565.png,43减35
cap_1566.png,?
```

UTF-8 无 BOM、LF 换行。必须覆盖**每一张新图**（含 `?` 的）。

## 3. 常见坑（前人踩过的）

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 编号从 0 重新开始 | 覆盖旧图，数据丢失 | 先扫现有最大编号，`--skip` 接着编 |
| 用"结果非负/整除"反推 | 标注系统性错误 | 只转录所见 |
| 减法 B 强行取一位 | `55减23` 标成 `55减2` | 两个实心同尺寸数字 = B 取两位 |
| 用系统 /tmp | 断电/清理后全丢 | 中间文件一律放 `dataset/tmp/` |
| CSV 带 BOM / CRLF | 下游解析出兼容性问题 | UTF-8 无 BOM + LF |
| 把 `=?` 标进标签 | 污染训练 | 标签只到 B 为止 |
