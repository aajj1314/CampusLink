# 发现：对比度增强预处理显著提升验证码可读性

> 记录一次预处理实验观察：把 `raw/` 里的算式验证码原图做**对比度拉伸**（约 ×2.5）后，
> 前景字符明显更清晰、"跳"出来，背景浅色干扰被压白。
> **推论**：让识别模型读处理后的图，准确率大概率高于直接读原图 —— 但**尚未跑模型指标验证**，
> 详见文末「待验证」。样本图见 `preprocess_samples/`。

---

## 1. 现象与证据

样例图（左=原图，右=对比度 ×2.5）：
[`preprocess_samples/cap_contrast_compare.png`](preprocess_samples/cap_contrast_compare.png)

- 覆盖 10 张不同区间的图：`cap_0000 / 0025 / 0050 / 0075 / 0100 / 0125 / 0150 / 0175 / 0200 / 0220`
- 单张三档增强（同一张 `cap_0001`）：`cap_0001_contrast_15.png`（×1.5）、
  `cap_0001_contrast_25.png`（×2.5）、`cap_0001_contrast_40.png`（×4.0）

观察结论（10 张上表现一致）：

| 现象 | 说明 |
|---|---|
| 前景字符变实 | 如 `30÷5=?`、`15-3=?`、`58×2=?`、`93-3=?`，笔画对比度提高、边缘更利落 |
| 浅色干扰被压白 | 淡蓝/淡紫的背景乱码串（`0123456778` 之类）大量褪成白色，画面更干净 |
| 噪声点减少 | 浅色小圆点/细斜线随对比拉伸被并到白底 |
| 副作用：颜色更艳 | 线性矩阵不只拉明暗，也拉颜色饱和度 → 前景变成更浓的原色（偏"花"） |

增强强度对比：×1.5 轻、底色仍噪；**×2.5 折中最干净**；×4.0 前景接近纯色但浅色笔画会被削平丢细节。
综合建议工作区间 **×2.5 ~ ×4.0**。

---

## 2. 处理方法

对每个像素做以**中灰 128 为锚点**的线性对比度拉伸，逐通道（R/G/B）独立处理：

```
out(x) = clip( round( (in(x) - 128) * k + 128 ), 0, 255 )
```

- `k` = 对比度倍数（本次取 2.5）
- `clip` 到 `[0, 255]`，超出截断（这就是"压白/压黑"的来源）
- 等价于 GDI+ 的 `ColorMatrix`（本次实现方式）：

```
[ k  0  0  0  0 ]
[ 0  k  0  0  0 ]
[ 0  0  k  0  0 ]
[ 0  0  0  1  0 ]
[ t  t  t  0  1 ]      其中 t = (1 - k) / 2     （归一化偏移）
```

---

## 3. 复现方式（Windows / 标准库，无需第三方包）

本机环境无 PIL / numpy，用 System.Drawing 的 `ColorMatrix` 实现，零依赖：

```powershell
Add-Type -AssemblyName System.Drawing
$img = [System.Drawing.Bitmap]::FromFile($src)
$out = New-Object System.Drawing.Bitmap $img.Width, $img.Height
$g   = [System.Drawing.Graphics]::FromImage($out)
$k   = 2.5
$t   = (1.0 - $k) / 2.0
$cm  = New-Object System.Drawing.Imaging.ColorMatrix
$cm.Matrix00 = $k; $cm.Matrix11 = $k; $cm.Matrix22 = $k
$cm.Matrix33 = 1.0; $cm.Matrix44 = 1.0
$cm.Matrix40 = [single]$t; $cm.Matrix41 = [single]$t; $cm.Matrix42 = [single]$t
$ia  = New-Object System.Drawing.Imaging.ImageAttributes
$ia.SetColorMatrix($cm)
$rect = New-Object System.Drawing.Rectangle 0, 0, $img.Width, $img.Height
$g.DrawImage($img, $rect, 0,0,$img.Width,$img.Height, [System.Drawing.GraphicsUnit]::Pixel, $ia)
$out.Save($destPath, [System.Drawing.Imaging.ImageFormat]::Png)
```

纯 Python（有 PIL 时）等价写法：

```python
from PIL import Image, ImageEnhance
ImageEnhance.Contrast(Image.open(src)).enhance(2.5).save(dst)
```

> 若模型管线用 OpenCV/PIL，优先用 `ImageEnhance.Contrast` / `cv2.convertScaleAbs(img, alpha=k, beta=128*(1-k))`，
> 与上面的矩阵等价。

## 4. 为什么可能有效（原理）

- 原图前景笔画与浅色背景的**亮度差本来就小**，模型编码器容易把淡色干扰与主字符混为一谈；
- 线性拉伸放大亮度差后，主字符与噪声在像素空间被拉开，**特征更可分**；
- 干扰元素多为浅色/低饱和度，拉伸时被 `clip` 到 255（白），等于**顺带做了背景抑制**，但不像阈值二值化那样不可逆地抹掉笔画。

---

## 5. 对模型的使用建议

1. **推理预处理**：在送入识别模型前，对输入图统一做 ×2.5 对比度增强。
2. **训练数据**：把「原图 + 增强图」一起作为样本（数据增强），让模型对亮度/对比度变化更鲁棒，
   而不是只见到增强后的分布（避免训练-推理分布不一致）。
3. 若要更彻底去背景，可在增强之后再加**灰度 + 自适应阈值二值化**，
   但二值化不可逆、会丢浅色笔画，建议单独做一组对照比较，不要直接替换。

## 6. 待验证 —— 已验证（2026-10-19，结论：对人眼有效，对模型负收益）

Windows 侧用 `ml/scripts/contrast_ab.py` 跑了 §6 要求的对照实验：
**同一模型**（`crnn_math.onnx`）、**同一独立测试集**（`test_raw/` 116 张，从未参与训练），
只变预处理。增强实现与本文公式逐像素等价（PIL `ImageEnhance.Contrast`）：

| 组 | 正确 | 错答 | 安全失败 | 答案正确率 | 错答率 |
|---|---|---|---|---|---|
| **A 基线 k=1.0** | **107** | **8** | 1 | **92.2%** | **6.9%** |
| B k=1.5 | 102 | 12 | 2 | 87.9% | 10.3% |
| C k=2.5 | 96 | 18 | 2 | 82.8% | **15.5%** |
| D k=4.0 | 72 | 38 | 6 | 62.1% | 32.8% |
| E k=2.5 灰度域 | 93 | 21 | 2 | 80.2% | 18.1% |

相对基线的迁移（k=2.5 组）：救回 3 张（原错答/失败 → 对），**弄坏 14 张**
（12 张对 → 错答，2 张对 → 失败）。净损失 11 张，且**错答率翻倍**。

### 结论

1. **不要在推理前做对比度增强。** 识别率随 k 单调恶化，×2.5 时错答率
   6.9% → 15.5%（翻倍），×4.0 是灾难（62.1%）。§1 的视觉观察对人眼成立，
   但模型的视觉统计是按**原图分布**学的。
2. **根因是训练-推理分布不一致**：训练增强里对比度抖动只有 ×0.8~1.2（见
   `train_crnn.py::_augment`），×2.5 远超这个范围。§5.2 的担忧是对的，
   而且比预想的严重 —— 即使"压白背景"减少了干扰，字符内部灰度层次被
   clip 削平的损失更大。
3. 举例：`52加5` → 增强后识别成 `5加5`（首位被削掉）、`18减6` → `48减6`
   （细笔画 `1` 被拉伸噪声污染）。
4. **这条预处理未来可能翻身的条件**：训练时若加入"强对比度增强"
   （TASK_ROUND2 任务 3 的增强升级若包含此项），新模型见过了这个分布，
   届时用 `contrast_ab.py` 重跑对照再下结论。工具保留。

## 7. 注意事项

- `raw/` 是**只读数据集**（HANDOFF 明确要求不改动/不覆盖，下游靠 `cap_XXXX.png` 计数）。
  本发现的产物统一放 `preprocess_samples/`（样例/证据）或 `tmp/`（中间件），**不要再往 `raw/` 里写增强图**。
- 增强是**线性色彩矩阵**，会同时提高颜色饱和度，不只是明暗；若模型对颜色敏感需注意。
- `k` 不宜过大：> ×4 时浅色笔画被削平，可能反而损失信息。
