# 03 · 核心数据结构

> 本文档定义跨模块共享的结构。原则：**敏感信息在 schema 层面就不存在**，而不是"约定不传"。

## 1. 领域对象

### VisionTask（视觉任务，Router 持有）

```python
@dataclass
class VisionTask:
    task_id: str            # "cap_" + 8 hex，Router 生成
    nonce: str              # 16 hex，提交时校验，防重放
    image: bytes            # 仅内存持有；任务结束即置 None（决策 D5）
    image_meta: ImageMeta   # format/width/height/bytes
    expect_length: int      # 门户档案 ocr_length
    charset_hint: str       # digits|lower|upper|alnum
    strategies_hint: tuple[str, ...]
    allow_manual: bool      # Desktop 识别失败后放宽为 True，转给 Mobile
    state: TaskState
    created_at: float
    expires_at: float       # created_at + TTL(90s)
    assigned_to: str | None # device_id
    result: TaskResult | None
    auth_attempt_id: str    # 内部关联到当次认证尝试（不外泄）
```

| 字段 | 谁能看 | 说明 |
|---|---|---|
| `image` | Router 内存 | 序列化时只出现在 `image_url` 指向的响应里 |
| `nonce` | Router + 领到任务的节点 | 任务领取时下发 |
| `auth_attempt_id` | **仅 Router** | 不出现在任何 API 响应中 |
| `result` | Router；节点可见自己的 | 节点不能看别人提交的结果 |

### TaskResult

```python
@dataclass
class TaskResult:
    text: str
    source: str             # "ocr" | "manual"
    confidence: float       # manual 时为 1.0
    detail: dict[str, str]  # 各策略输出（诊断用，无敏感内容）
    elapsed_ms: int
    submitted_at: float
```

### VisionNode / DeviceIdentity（配对设备）

```python
@dataclass
class DeviceIdentity:
    device_id: str          # "dev_" + 6 hex
    device_name: str        # 用户起的名字
    device_kind: str        # "desktop" | "mobile"
    token_hash: bytes       # SHA-256(token)；token 本体不存
    capabilities: list[str] # ["ocr", "manual"]
    created_at: float
    last_seen: float
    revoked: bool = False
```

> token 校验：`sha256(提供的token) == token_hash`。**Router 不存 token 明文**，
> 泄漏配置文件也拿不到有效凭据——这与 Desktop 端 keyring 的思路一致。

### AuthTask（一次认证尝试，Router 持有）

```python
@dataclass
class AuthTask:
    task_id: str            # "auth_" + hex
    state: str              # checking|submitting|online|failed|cancelled
    attempts: int
    message: str            # 给用户的中文提示（复用 friendly_error）
    raw_message: str        # 门户原样提示
    started_at: float
    finished_at: float | None
```

### PortalSessionRef（会话引用句柄）

**设计要点**：API 与内部模块之间传递的是"会话引用"，不是会话本身。

```python
@dataclass
class PortalSessionRef:
    session_id: str         # 内部 id，供日志关联（日志已脱敏）
    established_at: float
    state: str              # fresh|active|stale|expired
    # 注意：这里故意没有 cookies 字段。
```

真实 `requests.Session`（含 Cookie）只存在于 `PortalClient` 内部，由 Router 进程持有。这样：
- 视觉节点的 API schema 里**不可能**出现 Cookie（没有字段可序列化）
- 日志里即使打了 session 对象，也只有 id 和状态（配合 `logging_setup.scrub` 双保险）

## 2. 与现有代码的衔接（唯一改动点）

现有 `core/authenticator.py` 第 177 行直接调用 `ocr_mod.recognize()`。跨设备拆分引入后端抽象：

```python
# core/ocr_backend.py（新增，core 内）
class OcrBackend(Protocol):
    def recognize(self, image: bytes, *, length: int,
                  strategies: tuple[str, ...]) -> OcrResult: ...

@dataclass
class OcrResult:
    text: str
    confidence: float
    detail: dict[str, str]
    source: str             # "local" | "remote" | "manual"
```

```python
# 本地实现：包装现有 ocr.recognize()，行为与今天完全一致
class LocalDdddocrBackend:
    ...

# 远程实现：走 02 文档的视觉任务 API，同步等待（认证流程本身是串行重试的）
class RemoteVisionBackend:
    def __init__(self, taskmanager): ...
    # 提交图像 → 等待结果（带超时）→ 超时/失败返回空文本，
    # 让 authenticator 现有的"换一张重试"逻辑自然接管
```

`Authenticator.__init__` 加一个可选参数 `ocr_backend: OcrBackend | None = None`，
**默认 None 时内部构造 LocalDdddocrBackend**——现有 GUI/CLI/44 条测试**零改动**。

## 3. 状态机

### 任务状态机

```
                 领取(长轮询)          提交(带nonce)
  pending ────────────────> assigned ──────────────> submitted ──校验──> verified
     ▲  ▲                      │  │                     │
     │  │ TTL 90s              │  │ 节点30s未交           │ 长度/字符集不符
     │  └──────────────────────┘  ▼                     ▼
     │                     pending(重派)              rejected
     │ 认证流程结束(取消)                                    │
     ▼                                                    ▼
  cancelled <──────(任意状态，仅 Router 可发起)         pending(新任务)
```

不变式：
- `verified` / `rejected` / `expired` / `cancelled` 是终态，不可逆
- `nonce` 一经使用即作废（哪怕校验失败）
- 处于 `assigned` 的任务同时最多 1 个/节点（领取机制保证）

### 认证状态机（与现有 `NetworkState` 对齐）

```
unknown → checking → online
              │
              ├──> need_login ──(触发认证)──> checking
              └──> offline
```

Router 的 `/auth/status` 返回的 `state` 即此状态机；Desktop 独立模式使用本地同名状态机，两者语义一致所以 UI 代码不用分支。

## 4. Router 持久化（最小化）

| 数据 | 存哪 | 为什么 |
|---|---|---|
| 门户档案（profile JSON） | flash（/etc/campuslink/），低频写 | 换学校才改，写放大可忽略 |
| 设备与 token_hash | flash（/etc/campuslink/devices.json） | 必须重启存活 |
| 开关配置（auto_reconnect 等） | flash，低频 | 同上 |
| Cookie / 会话 / 验证码图片 / 任务队列 | **内存（tmpfs）** | 决策 D5/D8：时效数据 + NAND 保护 |
| 日志 | **tmpfs**，重启即清 | NAND 擦写寿命；需要留存时由 Desktop 拉取 |

## 5. 敏感信息边界总表

| 数据 | Router | Desktop | Mobile | 网络传输 | 持久化 |
|---|---|---|---|---|---|
| Portal Cookie | 内存 ✅ | ❌ | ❌ | ❌ 从不出 Router | ❌ |
| 账号/密码 | 内存 ✅ | 独立模式：keyring ✅ | ❌ | ❌ | 密码永不落盘（含 Router） |
| 验证码图片 | 内存 ✅ | 内存（处理中） | 内存 | 任务领取时 ✅（Bearer 保护） | ❌ |
| 识别结果文本 | 内存+日志(脱敏) | ✅ | ✅ | ✅ | 统计聚合（无原文） |
| device_token | hash ✅ | 系统凭据管理器 ✅ | Android Keystore ✅ | Bearer 头 ✅ | hash |
