# 06 · 风险评估与测试方案

## 1. 风险矩阵

概率/影响：低 L · 中 M · 高 H

| # | 风险 | 概率 | 影响 | 缓解 | 兜底 |
|---|---|---|---|---|---|
| R1 | **Portal 会话与 IP 绑定，Router WAN IP 认证后 NAT 客户端是否共享通过状态** | M | H | Phase 1 第一优先验证项；Portal 是 IP 基认证（实测多次重试同 IP 生效） | 若不共享：Router 模式仅对"Router 自身上网"有意义，产品价值重估 |
| R2 | **mipsel 上 Python 性能不可接受**（MIPS 无 NEON，单核 880 MHz） | M | H | 认证流程是 IO 密集（HTTP 等待占 95%+ 时间），CPU 只做字符串处理，预估单次认证 CPU 占用 < 2 s | 止损点见路线图 Phase 1：降级为状态聚合器 |
| R3 | **内存 OOM**（128 MB，OpenWrt+无线驱动已占 ~50 MB） | L | H | RAM 预算表（04 文档）；不装视觉栈；任务图像 < 2 KB/张 | oomkiller 保护 + 看门狗 init 脚本自动拉起 |
| R4 | **NAND 磨损 / overlay 写满** | M | M | 日志/队列走 tmpfs（D5/D8）；`overlay_free_mb` 告警 | overlay 满时自动禁用配置写，只保留内存态 |
| R5 | **双登录并发冲突**（Router 与 PC 同时认证同一账号） | H(若不设计) | M | Router 托管模式下 Desktop 禁用本地认证（01 文档）；UI 明示当前模式 | 并发超限错误如实透传（`friendly_error` 已覆盖） |
| R6 | **任务泄漏**（节点离线导致任务悬空） | H | L | 30 s 未提交回 pending；TTL 90 s；认证结束统一 cancel | Router 兜底超时取消 |
| R7 | **重放/未授权访问 API** | M | M | Bearer token（仅存 hash）、一次性 nonce、PIN 单次有效、可吊销 | 检测异常尝试时吊销全部设备并要求重新配对 |
| R8 | **协议版本漂移**（Router 先升级，客户端旧） | M | L | URL 版本 + `/capabilities` 协商 + v1/v2 共存期 | 客户端不识别的版本走"只读降级" |
| R9 | **门户行为变化**（表单/验证码改版） | M | H | 档案化配置（换学校只改 JSON）；`PortalChanged` 异常明确上报 | 现有 Desktop 独立模式不受影响；probe 工具重新生成档案 |
| R10 | **Vision Lite 投入失控** | M | L | 95% 识别率硬门槛 + 2 周时限 | 归档结论，明确"放弃"也是交付 |

## 2. 测试策略

### 2.1 单元与回归（已存在，直接复用）

现有 44 条 pytest 覆盖门户协议、配置/凭据/日志脱敏、模拟门户端到端。**Phase 2 的 `OcrBackend` 改动必须保持 44 条全绿且零修改**——这是"默认行为不变"的回归保证。

新增测试随各阶段补充：

| 阶段 | 新增测试 |
|---|---|
| P1 | Router 上跑现有 44 条（mipsel 兼容性冒烟）；netdetect 的 Linux 网关读取分支（已有实现，补单测） |
| P2 | API 契约测试（schema 快照 + 状态机不变式：终态不可逆、nonce 单次、单节点单任务）；降级切换测试 |
| P3 | Mobile 与 Desktop 同模型识别率对比；长轮询断连恢复 |

### 2.2 契约测试（API 是跨团队契约）

- **Schema 快照**：每个端点录制「请求/响应」样例对，CI 里比对——字段增删必须显式更新快照，防止无意破坏
- **状态机属性测试**：随机操作序列（领取/提交/超时/取消）后断言不变式（无 `verified`→`pending`、nonce 不可复用、终态数量守恒）
- **敏感字段扫描**：对所有响应做自动化扫描，断言不含 `cookie`/`password`/`token`（除配对响应的 token 本身）——把 03 文档的边界表变成 CI 断言

### 2.3 硬件在环（HIL，Phase 1 起持续）

| 测试 | 方法 | 通过标准 |
|---|---|---|
| 冷启动 | 断电 → 上电 | 90 s 内 API 可用，120 s 内完成重连 |
| 长稳 | 48 h 常驻 | RSS 增长 < 5 MB；无任务泄漏 |
| 断网恢复 | 拔 WAN → 插回 | 60 s 内重新认证成功 |
| 视觉节点闪断 | Desktop 杀进程再起 | 任务 30 s 重派，认证不失败 |
| overlay 压力 | 循环改配置 1000 次 | overlay 增长可忽略；写放大符合预期 |
| 并发登录 | Router 认证同时 PC 发起认证 | PC 收到明确阻止提示，门户侧无并发错误 |

### 2.4 安全测试

- token 吊销后旧 token 立即失效（401）
- PIN 重放/爆破：错误 5 次后锁定配对 5 min
- 图像端点在任务过期后返回 410
- 全响应体敏感字段扫描（见 2.2）
- LAN 边界：从 WAN 口扫描确认 API 不可达

## 3. 需要你拍板的开放问题

1. **R1 的实测窗口**：Portal 会话按 IP 绑定的行为需要 Phase 1 在真机上验证，建议列为第一优先级——它决定 Router 模式的产品价值上限。
2. **Desktop 是否允许加 `zeroconf` 依赖**：不加就手输 IP（现状可接受）。
3. **Mobile 的 flavor 策略**：轻量版（无 CV、纯人工）是否作为默认发布版本。
4. **v1.0.0 vs v1.0**：安装包版本号是否在本阶段统一（现状 1.0.0）。
