# 05 · 分阶段研发路线图

> 原则：每个阶段独立交付可用价值；任何阶段中止都不破坏上一阶段的成果；Windows 稳定版始终可用。

## Phase 0 · 设计定稿（本阶段，已完成）

**产出**：本设计文档集（00–06）。
**不做**：任何实现。

**定稿标准**：
- [x] 现状核对完成（解耦程度、OCR 接缝、硬件约束）
- [x] API 规范覆盖任务书全部要求（版本/配对/任务/状态/图像/结果/取消/过期/错误码/能力）
- [x] 敏感信息边界在 schema 层面成立
- [x] 合规边界明确
- [ ] **评审**：由你确认后进入 Phase 1 ← 当前待办

## Phase 1 · Router MVP（预计 2–3 周）

**目标**：Router 能自己完成认证（OCR 暂时用"人工经 Desktop 转发"或干脆只做只读状态），并暴露状态 API。
**为什么这样切**：先验证最大的技术风险——core 在 mipsel 上真的能跑、门户会话在 Router WAN IP 上真的有效。这一步不成立，后面的视觉协作都无意义。

| 项 | 内容 |
|---|---|
| 范围 | vendor 依赖、`portal/netdetect/authenticator` 移植、`/health` `/capabilities` `/auth/status` `/system/status`、init 脚本 |
| 明确不做 | 视觉任务分发、Mobile、配对（本阶段仅本机 CLI 配置） |
| 验收 | 1) R2100 刷 OpenWrt 25.12.2 成功；2) Router 上触发认证返回"认证成功"；3) 断电重启后自动重连；4) 48 h 常驻内存增长 < 5 MB；5) overlay 剩余 ≥ 25 MB |

**风险止损点**：若 core 在 mipsel 上性能不可接受（单次认证 > 60 s）或内存超预算，回退设计——Router 只做状态查询，认证仍在 PC（砍掉 D1，架构退化为"状态聚合器"）。这个止损点必须提前想清楚。

## Phase 2 · Vision API + Desktop 接入（预计 2 周）

**目标**：Router 托管模式完整可用——Router 认证时由 Desktop 做 OCR。

| 项 | 内容 |
|---|---|
| Router | 任务管理器 + 视觉端点 + 配对（PIN/token/吊销） |
| Desktop | `OcrBackend` 抽象 + `LocalDdddocrBackend` + 视觉节点角色（默认关）+ 降级逻辑 |
| 测试 | 契约测试（API schema 快照）+ 现有 44 条测试全绿（`OcrBackend` 默认实现不改行为） |

**验收**：
- [ ] Desktop 开关节点后，Router 认证全流程成功（含验证码去重重试路径）
- [ ] Desktop 关闭节点/杀进程，任务 30 s 内重派（或转人工标记）
- [ ] Router 失联 6 s → Desktop 自动回独立模式；Router 恢复 → 重新托管
- [ ] 双向并发冲突测试：Router 托管时 PC 手动点"立即连接"被阻止并给出提示
- [ ] 协议 v1 契约测试通过；token 吊销后旧设备 401

## Phase 3 · Mobile（预计 3 周）

**目标**：手机作为第二个视觉节点，人工输入兜底。

| 项 | 内容 |
|---|---|
| 范围 | 配对、长轮询、OpenCV/onnxruntime 识别、人工输入 UI、只读状态页 |
| 特有 | `allow_manual` 任务流：Desktop OCR 失败 → 任务标记允许人工 → 手机弹出看图输字 |

**验收**：
- [ ] 手机 OCR 识别率与 Desktop 同一模型下 ±5% 以内
- [ ] 飞行模式/杀后台不产生任务泄漏（30 s 重派验证）
- [ ] 人工输入路径端到端 < 15 s（看图 → 提交 → 认证完成）

## Phase 4 · Vision Lite 预研（预计 2 周，可随时中止）

按 01 文档 L1–L4 门槛执行，**识别率 ≥ 95% 才立项，否则放弃并归档结论**。
不设"再努力一下"的例外——避免在 128 MB 的 MIPS 设备上无限投入。

## 阶段依赖与并行度

```
Phase 0 ──> Phase 1 ──> Phase 2 ──> Phase 3
                │            │
                │            └── Desktop 侧改动可提前开发（本地 OcrBackend 先行）
                └── Vision Lite L1 数据采集可与 Phase 1 并行（互不依赖）
Phase 4 依赖 Phase 1（需要 Router 上的采集环境）
```

## 里程碑总览

| 阶段 | 时长 | 关键交付 | 止损点 |
|---|---|---|---|
| P0 | 0.5 周 | 设计文档 | 评审不通过则修订 |
| P1 | 2–3 周 | Router 认证 MVP + 只读 API | mipsel 性能/内存不可行 → 降级为状态聚合器 |
| P2 | 2 周 | 托管模式全流程 | API 复杂度失控 → 缩减为图像直传（不做任务队列） |
| P3 | 3 周 | Mobile 节点 | 人工输入路径优先，OCR 路径可砍 |
| P4 | 2 周 | Vision Lite 结论（含"放弃"也是结论） | 识别率 < 95% → 归档 |
