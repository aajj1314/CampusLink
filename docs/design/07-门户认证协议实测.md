# 07 · 门户认证协议实测

> 版本 1.0 · 2026-10-16 · 状态：实测确认
> 实测对象：桂林信息科技学院「多运营商接入管理平台统一认证系统」
> 实测方式：受控浏览器（Network 面板 + 页面 DOM 只读观察）走**一次本人账号的正常登录**
>
> **合规声明**：仅分析本人有权使用的认证流程；未重放任何请求，未绕过验证码或其它访问控制；
> 注销流程未执行（账号保持在线，由账号所有者决定）。文档内所有账号、密码、会话 Cookie、
> 客户端真实 IP 一律以占位符表示。

---

## 1. 结论先行

1. **现有 Windows 版的协议层（GET / POST / 结果判定）与线上门户 1:1 吻合**，无需重新抓包。
   本文是一次**核对性实测**，不是重新逆向。
2. 源码唯一可微调处：注释里「成功/失败共用 `<p class="validation-summary-errors">` 容器」
   这一说法未被本次实测确认；实测成功提示以**纯文本「联网成功!」**出现在返回页表格行内。
   判定逻辑本身不受影响（`check_success` 用的是**文本包含**，恰好命中）。
3. 源码**尚未覆盖**两处能力，Silent 若要「主动下线 / 权威在线态判定」需补：
   - `GET /logoff` 页面里的**权威在线状态**（`当前在线状态：已联网`）
   - `POST /logoff` 注销流程（**同样需要验证码**）

## 3. 端点总表

实测一次登录过程中，浏览器 Network 面板记录到的请求：

| # | 方法 + 路径 | 类型 | 说明 |
|---|---|---|---|
| 0 | `GET /login` | Document | 打开登录页 |
| 2 | **`POST /login`** | Document | **登录提交（关键请求）** |
| 4 | `GET /CheckCode` | Image | 验证码图片 |
| 6 | `GET /logoff?lrl=1` | Document | 断开网络页 |
| — | `GET /checking` | Document | 信息验证页（导航中发现） |
| — | `GET /Content/Site.css` | Stylesheet | 静态资源 |
| — | `GET /@vite/client` | Script | 报 `net::ERR_ABORTED`，可忽略 |

导航链接（`url` 为相对路径）：`主页 → ./`、`连网登录 → login`、`断开网络 → logoff`、`信息验证 → checking`。

> `POST /login` 的资源类型是 **Document**，说明服务端返回的是**完整 HTML 页面**（WebForms 回发），
> **不是 JSON**。这决定了客户端判定必须走「响应文本」而不是解析 JSON。

## 4. 登录流程

### 4.1 请求

```
POST http://10.6.6.6/login
Content-Type: application/x-www-form-urlencoded
Referer: http://10.6.6.6/login
```

- `action` 取页面 `<form action="./login">`，即 `http://10.6.6.6/login`
- 方法 `POST`
- 提交时**必须带上** `LoginBtn`（ASP.NET 靠按钮 name 判断触发哪个回发）

### 4.2 表单字段（实测完整清单）

| 字段名 | 含义 | 备注 |
|---|---|---|
| `__VIEWSTATE` | WebForms 视图状态 | **每次动态**，必须从当次登录页现取 |
| `__VIEWSTATEENCRYPTED` | 视图状态加密标记 | 动态 |
| `__VIEWSTATEGENERATOR` | 视图状态生成器 | 动态 |
| `__EVENTVALIDATION` | 事件校验 | **每次动态** |
| `ctl00$MainContent$TextBoxISP` | 运营商 | `readonly`；登录前显示「自动选择」，登录后服务端填为「中国电信」 |
| `ctl00$MainContent$SSOGUITID` | 学(工)号 | 用户输入 |
| `ctl00$MainContent$SSOACC` | 上网账号 | 用户输入 |
| `ctl00$MainContent$SSOPWD` | 密码 | 用户输入，**明文** |
| `ctl00$MainContent$TextBoxCC` | 验证码 | 用户输入 |
| `ctl00$MainContent$CheckBoxSaveMe` | 保存登录信息 | 复选框，可不勾 |
| `ctl00$MainContent$LoginBtn` | 登录按钮 | submit，**必须带** |

> 页面上「当前用户IP」显示的是客户端局域网地址（示例值占位为 `192.0.2.88`），
> 服务端据此判断是否可用。

### 4.3 最小提交载荷（占位符示例）

```
__VIEWSTATE=<当次页面取值>
__VIEWSTATEGENERATOR=<当次页面取值>
__EVENTVALIDATION=<当次页面取值>
ctl00$MainContent$TextBoxISP=自动选择
ctl00$MainContent$SSOGUITID=<学工号>
ctl00$MainContent$SSOACC=<上网账号>
ctl00$MainContent$SSOPWD=<密码>
ctl00$MainContent$TextBoxCC=<验证码>
ctl00$MainContent$LoginBtn=登录
```

## 5. 验证码

| 项 | 实测值 |
|---|---|
| 图片地址 | `GET /CheckCode`（登录页内 `<img src="/CheckCode">`） |
| 长度 | 4 位（字母数字混合，实测样本如 `8ypx`） |
| 刷新机制 | 同一会话连续请求可能返回同一张；重新 `GET /login` 后再取会换图 |
| 注销页 | `/logoff` 页**同样**带一张 `/CheckCode` 验证码 |

> 源码 `captcha_url="auto"`（从页面 `<img>` 现找）在实测中正确命中 `/CheckCode`。
> 若想更稳，可在档案里把 `captcha_url` 固定写为该地址。

## 6. 成功 / 失败判定

### 6.1 实测行为

登录**成功后页面不跳转、不 302**，登录表单继续渲染，仅在表格内多出一行提示：

```
联网成功!
```

（同时 `TextBoxISP` 由「自动选择」被服务端改写为「中国电信」。）

这解释了为什么源码的判定必须是「**文本包含**」而不能用「表单消失 / 容器为空 / 跳转成功」这类推断式条件——
见 [portal.py](../../campuslink/core/portal.py) 顶部注释与 `check_success()`。

### 6.2 与源码的对应

| 实测事实 | 源码落点 |
|---|---|
| 成功标识为文本「联网成功」 | 档案 `success_check = {"type":"contains","value":"联网成功"}` |
| 响应是 HTML 而非 JSON | `check_success` 基于 `resp.text` |
| 成功/失败同页渲染 | 必须用文案匹配，代码已如此实现 |

### 6.3 待补

- **失败提示的原文与容器**：本次未做失败登录，未采集。源码 `extract_message()` 的候选容器
  （`validation-summary-errors` / `field-validation-error` / `error` / `tips` / `msg`）与
  `ERROR_HINTS` 关键词表**未在本次实测中验证**，建议后续用一次「故意输错验证码」的登录补齐。

## 7. 在线态判定与注销

### 7.1 权威在线态（新增发现）

`GET /logoff` 页面直接显示服务端权威状态：

```
当前用户IP      192.0.2.88
当前在线状态    已联网
验证码          （图片）
[注销]          按钮
```

这比用 `generate_204` 探针更权威（探针只能间接推断），可作为 Silent **在线态判定**的首选信号。

### 7.2 注销流程（新增发现）

```
GET  /logoff            → 断开网络页（含验证码）
POST /logoff?lrl=1      → 提交验证码 + 点击「注销」
```

注销**也需要验证码**，源码目前**未实现**该流程。

## 9. 给 CampusLink Silent 的落地建议

1. **协议层零改动**：直接复用 `PortalClient`，无需重新抓包或改写。
2. **在线态**：优先读 `GET /logoff` 的「当前在线状态」，`generate_204` 退为兜底。
3. **注销能力**：如需「主动下线」，新增 `GET /logoff` → `POST /logoff?lrl=1`（带验证码），
   档案里补一对字段映射（`logout_url` / 注销字段名）。
4. **验证码**：Silent 的视觉节点链路已适配 `/CheckCode` 4 位图；把 `captcha_url` 固定为
   `/CheckCode` 可少一次页面解析。
5. **不要做的**：不重放请求、不做多账号/共享、不做 MAC 轮换；并发超限如实上报。
