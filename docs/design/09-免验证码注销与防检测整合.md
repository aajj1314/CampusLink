## 二、注销协议（实测）

### 2.1 端点

```
GET  /logoff?lrl=1     → 断开网络页（含验证码）
POST /logoff?lrl=1     → 提交验证码 + 注销
```

注意：`lrl=1` 这个查询参数**必须保留**，它是「直接跳转」标记。

### 2.2 表单字段（实测完整清单）

```
__VIEWSTATE              动态，每次页面都不同
__VIEWSTATEGENERATOR     = C04F0937（固定）
__VIEWSTATEENCRYPTED    = 空字符串
__EVENTVALIDATION        动态
ctl00$MainContent$TextBoxCC      验证码输入（maxlength=4）
ctl00$MainContent$LogoffBtn      注销按钮，value="注销"，必须带
```

**`LogoffBtn` 的坑**：HTML 里它带 `disabled="disabled" class="aspNetDisabled"`，
这是前端在验证码为空时的禁用态。**POST 时把 name/value 带上就行**，服务端不看这个属性。

### 2.3 页面状态字段

```html
当前用户IP    172.22.67.139        ← Cudy 的 WAN IP
当前在线状态  未联网 / 已联网
```

这两个字段是**权威在线态**，比 `generate_204` 探针可靠（`07-门户认证协议实测.md §7.1` 已指出）。

### 2.4 验证码

| 项 | 值 |
|---|---|
| 端点 | `/CheckCode` |
| 尺寸 | **80×24** PNG |
| 类型 | **4 位字符**（字母数字混合，大小写都有） |
| 刷新 | **每次请求都是新图**（实测 30 张，md5 无一重复） |
| 对比 | 登录页用 `/ACaptcha.ashx`，200×60，算式 `5乘0=?` |

**关键差异**：注销验证码**每次换图**，不需要登录页那套「换会话重取」的复杂逻辑。

实测 30 张样本：
```
长度分布: {4位: 29张, 3位: 1张}
字符集:   2345689GPacdeghjkmnprstwxy
空结果:   0 / 30
```
注意有 1 张识别成 3 位 —— **长度不强制校验**，识别出几位就提交几位。

### 2.5 失败判据（实测确认）

```
错误验证码 "!!!!"  → <p class="validation-summary-errors">验证码错误!</p>
正确验证码 "dl2m"  → <p class="validation-summary-errors">(空)</p>
```

**判据**：`extract_message()` 返回的文本包含「验证码错误」→ 换图重试。

### 2.6 成功判据（已实现五分支）

实测发现一个**关键语义问题**：账号本来就未联网时，提交注销没有任何可观察的成功信号。

```
提交前「未联网」+ 提交格式正确的验证码
→ 页面照旧「未联网」，无报错、无成功文案
→ 无法区分「注销成功」和「什么也没发生」
```

实测确认（2026-11-18 21:55）：连续 5 次提交，**全部没有「验证码错误」**，
说明服务端接受了请求，只是没有会话可断。

所以 `_judge_logout()` 实现为**五分支**：

| reason | 条件 | ok | 说明 |
|---|---|---|---|
| `captcha_error` | 页面含「验证码错误」 | ❌ | **唯一必须重试的失败** |
| `success_hint` | 命中 `LOGOFF_SUCCESS_HINTS` | ✅ | 兼容方案，待实测校准 |
| `state_changed` | 已联网 → 未联网 | ✅ | 最可靠的兜底 |
| `already_offline` | 提交前后都是未联网 | ✅ | **目标状态已达成，不算失败** |
| `unknown` | 其它 | ❌ | 记录原文，继续重试 |

**为什么 `already_offline` 判成功**：
用户的目标是"不再占用会话名额"。本来就是未联网 = 目标已达成。
判失败会让用户误以为程序坏了，反复重试也没有意义。

**待校准**：`LOGOFF_SUCCESS_HINTS` 里的文案是推测的，需要真实在线账号
跑一次注销、抓到真实成功页后补进来。现在有 `state_changed` 兜底，
即使文案全不匹配也能正常判成功。

### 3.2 新增：`core/portal.py` 的 `LogoutPage` 与相关方法

```python
@dataclass
class LogoutPage:
    """一次「打开注销页」的产物。"""
    base_url: str
    action: str
    method: str
    fields: dict[str, str] = field(default_factory=dict)
    captcha_url: str = ""
    online_state: str = ""      # 「已联网」/「未联网」/空
    user_ip: str = ""
    html: str = ""


class PortalClient:
    # ... 现有方法 ...

    def open_logout_page(self) -> LogoutPage:
        """
        打开注销页。

        与 open_login_page 的差异：
          · 不需要「已在线」的特殊处理 —— 未在线时页面正常返回
          · 必须解析出「当前在线状态」，这是权威信号
        """
        url = self.profile.logout_url or urljoin(
            self.profile.portal_url, "/logoff?lrl=1")

        try:
            resp = self.session.get(url, timeout=self.profile.timeout)
        except requests.exceptions.RequestException as exc:
            raise NetworkUnreachable(str(exc), "注销页打不开") from exc

        resp.encoding = resp.apparent_encoding or resp.encoding
        html, base = resp.text, resp.url

        soup = BeautifulSoup(html, "lxml")
        form = self._pick_logout_form(soup)
        if form is None:
            raise PortalChanged(
                f"注销页里没有解析到表单（长度 {len(html)}）",
                "注销页面结构已变化，可能需要更新门户配置")

        return LogoutPage(
            base_url=base,
            action=urljoin(base, form.get("action") or base),
            method=(form.get("method") or "POST").upper(),
            fields=self._parse_fields(form),
            captcha_url=self._locate_captcha(soup, base),
            online_state=_extract_online_state(html),
            user_ip=_extract_user_ip(html),
            html=html,
        )

    @staticmethod
    def _pick_logout_form(soup):
        """
        注销页的表单识别。

        不能复用 _pick_login_form —— 那里优先找含 password 的表单，
        注销页没有密码框。
        这里按「有 LogoffBtn 或含 logoff 的 action」识别。
        """
        forms = soup.find_all("form")
        for f in forms:
            action = str(f.get("action") or "")
            if "logoff" in action.lower():
                return f
            for tag in f.find_all("input"):
                name = str(tag.get("name") or "")
                if "LogoffBtn" in name or "Logoff" in name:
                    return f
        return forms[0] if forms else None

    def fetch_logout_captcha(self, page: LogoutPage) -> bytes:
        """
        取注销验证码。

        与登录验证码的关键差异：/CheckCode 每次请求都是新图（实测），
        所以只需要加时间戳破缓存，不需要换会话。
        """
        url = self.profile.logout_captcha_url or page.captcha_url
        if not url:
            return b""
        url = urljoin(page.base_url, url)

        sep = "&" if "?" in url else "?"
        try:
            r = self.session.get(
                f"{url}{sep}_t={int(time.time() * 1000)}",
                timeout=self.profile.timeout,
                headers={"Referer": page.base_url})
            r.raise_for_status()
            return r.content
        except requests.exceptions.RequestException as exc:
            raise NetworkUnreachable(str(exc), "注销验证码下载失败") from exc

    def build_logout_payload(self, page: LogoutPage,
                             captcha_text: str) -> dict[str, str]:
        """页面字段 + 验证码 + 注销按钮 = 提交内容。"""
        payload = dict(page.fields)
        fmap = self.profile.logout_field_map or {}

        target = fmap.get("captcha")
        if target:
            for fname in re.split(r"[|,]", target):
                fname = fname.strip()
                if fname:
                    payload[fname] = captcha_text

        # ASP.NET 回发必需：按钮的 name=value
        if self.profile.logout_submit_name:
            payload[self.profile.logout_submit_name] = (
                self.profile.logout_submit_value or "注销")

        return payload

    def submit_logout(self, page: LogoutPage,
                      payload: dict[str, str]) -> requests.Response:
        action = self.profile.logout_url or page.action
        method = (page.method or "POST").upper()
        try:
            if method == "POST":
                return self.session.post(
                    action, data=payload, timeout=self.profile.timeout,
                    headers={"Referer": page.base_url})
            return self.session.get(
                action, params=payload, timeout=self.profile.timeout,
                headers={"Referer": page.base_url})
        except requests.exceptions.RequestException as exc:
            raise NetworkUnreachable(str(exc), "提交注销请求失败") from exc
```

### 3.3 新增：`core/authenticator.py` 的 `logout()` 方法

```python
#: 注销成功文案候选（实测后校准）
LOGOFF_SUCCESS_HINTS = (
    "注销成功", "断开成功", "已注销", "已断开",
)


def _extract_online_state(html: str) -> str:
    """从页面里抠「当前在线状态」的值。"""
    m = re.search(r"当前在线状态[\s:：]*([^\s<，。]+)", html)
    return m.group(1) if m else ""


class Authenticator:
    # ... 现有方法 ...

    def logout(
        self,
        *,
        cancel: CancelFn | None = None,
        on_progress: ProgressFn | None = None,
        on_captcha: CaptchaFn | None = None,
        ask_captcha: "AskCaptchaFn | None" = None,
        min_confidence: float = 0.90,
    ) -> LoginResult:
        """
        免验证码注销。

        与 login() 的差异：
          · 不需要 Credentials（注销只要验证码）
          · 验证码每次换图，不需要换会话去重
          · 重试次数更多（logout_max_retry=10），因为失败成本低
          · 成功后**不自动登录**（用户要腾出会话名额）

        min_confidence: ddddocr 置信度门限。低于此值不提交，直接换图。
        """
        say = _Say(on_progress)
        aborted = _Cancel(cancel)
        profile = self.profile

        client = PortalClient(profile)
        last_raw = ""
        last_reason = ""
        before_state = ""

        for attempt in range(1, profile.logout_max_retry + 1):
            if aborted:
                return _cancelled()

            # --- 1) 打开注销页（每次重开，隐藏域是动态的）---
            say(f"第 {attempt}/{profile.logout_max_retry} 次尝试：打开注销页…")
            try:
                page = client.open_logout_page()
            except PortalChanged as exc:
                return LoginResult(False, exc.user_message, NetworkState.UNKNOWN,
                                   attempts=attempt - 1, detail=exc.detail)
            except NetworkUnreachable as exc:
                return LoginResult(False, exc.user_message, NetworkState.OFFLINE,
                                   attempts=attempt - 1, detail=exc.detail)

            if attempt == 1:
                before_state = page.online_state
                say(f"当前在线状态：{before_state or '未知'}")
                # 未在线时提示一下，但仍然继续（可能要清残留会话）
                if before_state == "未联网":
                    say("提示：账号当前显示未联网，注销可能无实际效果")

            if aborted:
                return _cancelled()

            # --- 2) 取验证码 ---
            try:
                img = client.fetch_logout_captcha(page)
            except NetworkUnreachable as exc:
                say(f"验证码下载失败：{exc.user_message}")
                img = b""

            if not img:
                return LoginResult(False, "注销页没有验证码，可能页面已变化",
                                   NetworkState.UNKNOWN, attempts=attempt)

            # --- 3) 识别（带置信度）---
            ocr_result = self._backend().recognize(
                img, length=profile.logout_captcha_length,
                strategies=("raw", "gray"))
            captcha_text = ocr_result.text
            conf = ocr_result.confidence

            if on_captcha:
                try:
                    on_captcha(img, captcha_text)
                except Exception:
                    pass

            # --- 3.5) 置信度门限：拿不准就换图，不冒险提交 ---
            if captcha_text and conf < min_confidence:
                say(f"验证码把握不足（{conf:.0%} < {min_confidence:.0%}），换一张")
                captcha_text = ""

            # --- 3.6) 10 次都失败才手工兜底 ---
            if not captcha_text and ask_captcha is not None:
                if attempt >= profile.logout_max_retry - 1:
                    if aborted:
                        return _cancelled()
                    try:
                        manual = ask_captcha(img, captcha_text)
                    except Cancelled:
                        return _cancelled()
                    except Exception:
                        manual = None
                    if manual and manual.strip():
                        captcha_text = manual.strip()
                        say("已采用人工输入的验证码")

            if not captcha_text:
                say("验证码没认出来，换一张重试")
                time.sleep(RETRY_DELAY)
                continue

            say(f"验证码 {captcha_text}（把握 {conf:.0%}），提交注销…")

            # --- 4) 提交 ---
            payload = client.build_logout_payload(page, captcha_text)
            try:
                resp = client.submit_logout(page, payload)
            except NetworkUnreachable as exc:
                return LoginResult(False, exc.user_message, NetworkState.OFFLINE,
                                   attempts=attempt, detail=exc.detail)

            # --- 5) 判定 ---
            raw = extract_message(resp)
            last_raw = raw

            if "验证码错误" in resp.text or "验证码错误" in raw:
                say(f"验证码错误（{attempt}/{profile.logout_max_retry}）")
                last_reason = "captcha_error"
                time.sleep(RETRY_DELAY)
                continue

            # 成功文案
            for hint in LOGOFF_SUCCESS_HINTS:
                if hint in resp.text:
                    return LoginResult(True, hint, NetworkState.NEED_LOGIN,
                                       attempts=attempt, raw_message=raw)

            # 在线状态变化
            after_state = _extract_online_state(resp.text)
            if before_state == "已联网" and after_state == "未联网":
                return LoginResult(True, "已注销", NetworkState.NEED_LOGIN,
                                   attempts=attempt, raw_message=raw)

            # 不确定 —— 记录原文，继续重试
            last_reason = f"unknown:{raw[:60] if raw else '(空)'}"
            say(f"注销结果不确定（{last_reason}），重试")
            time.sleep(RETRY_DELAY)

        return LoginResult(
            False,
            f"注销失败（{last_reason or '多次尝试后仍未成功'}）",
            NetworkState.UNKNOWN,
            attempts=profile.logout_max_retry,
            raw_message=last_raw)
```

### 3.4 新增：ddddocr 置信度支持

**关键发现**：`ddddocr` 支持 `probability=True` 直接返回置信度，不需要多策略投票估算。

实测：
```python
d = ddddocr.DdddOcr(show_ad=False)
result = d.classification(img, probability=True)
# 返回 {'text': 'dl2m', 'confidence': 0.997, ...}
```

**修改 `core/ocr.py`**：新增一个带置信度的识别函数。

```python
def recognize_with_confidence(image: bytes) -> tuple[str, float, dict]:
    """
    单次识别，返回 (文本, 置信度, 明细)。

    与 recognize() 的差异：
      · 不做多策略投票（注销场景不需要，每次换图更快）
      · 直接用 ddddocr 的 probability 输出，置信度更准

    降级：ddddocr 版本不支持 probability 时，返回 confidence=1.0
    （视为可信），不阻塞流程。
    """
    try:
        import ddddocr
    except ImportError as exc:
        raise ImportError(f"ddddocr 未安装：{exc}") from exc

    d = _get_ddddocr()          # 单例，避免重复加载模型
    try:
        r = d.classification(image, probability=True)
        if isinstance(r, dict):
            return r.get("text", ""), float(r.get("confidence", 1.0)), r
        return str(r), 1.0, {"raw": str(r)}
    except TypeError:
        # 老版本 ddddocr 不支持 probability
        r = d.classification(image)
        return str(r), 1.0, {"raw": str(r)}
```

**修改 `core/ocr_backend.py`**：`LocalDdddocrBackend` 增加 `logout` 模式。

```python
class LocalDdddocrBackend:
    def __init__(self, mode: str = "text"):
        self._mode = mode if mode in ("text", "math", "logout") else "text"

    def recognize(self, image, *, length, strategies):
        if self._mode == "math":
            return self._recognize_math(image, started)
        if self._mode == "logout":
            return self._recognize_logout(image, started)
        # ... text 分支不变 ...

    def _recognize_logout(self, image, started):
        """注销验证码：80×24 字符，ddddocr 带置信度。"""
        from . import ocr
        try:
            text, conf, detail = ocr.recognize_with_confidence(image)
        except ImportError as exc:
            return OcrResult(text="", confidence=0.0,
                             detail={"_reason": f"ddddocr 不可用（{exc}）"},
                             source="local-logout", elapsed_ms=0)
        return OcrResult(
            text=text, confidence=conf, detail=detail,
            source="local-logout",
            elapsed_ms=max(0, int((time.monotonic() - started) * 1000)))
```

**为什么要单独一个 mode**：
- `text` 模式用多策略投票，适合登录页（要求高准确率）
- `logout` 模式单次识别 + 置信度，因为注销验证码简单（置信度 0.97+），且每次换图，重试成本低

## 四、防检测整合（Windows 侧）

### 4.1 当前状态

`core/hotspot.py` 已经实现了 TTL 修复：

```python
FILTER_INBOUND  = "inbound and ip and ip.TTL <= 1"
FILTER_OUTBOUND = "outbound and ip and (ip.TTL == 63 or ip.TTL == 127)"
TTL_TARGET = 64
```

**这套逻辑是正确的**，和路由器方案原理一致：
- `inbound TTL<=1` → 修回 64（救校园网 TCP 代理的 SYN-ACK）
- `outbound 63/127` → 归一成 64（防私接检测）

### 4.2 需要补的两项

#### 4.2.1 UA 归一（新增）

Windows 侧没有 ua2f，需要用 WinDivert 做 HTTP User-Agent 改写。

**可行性分析**：

| 项 | 评估 |
|---|---|
| WinDivert 能否改 TCP payload | ✅ 可以（`packet.payload` 是完整以太网帧） |
| 能否只改 UA 而不改长度 | ⚠️ 需要**等长替换**（和 ua2f 一样的限制） |
| 是否影响校验和 | ✅ WinDivert 自动重算 |
| 性能开销 | ⚠️ 所有 HTTP 包都要过用户态，有开销 |

**实现思路**（与 ua2f 对齐）：

```python
# core/ua_mask.py（新文件）

UA_PATTERN = re.compile(rb"User-Agent:\s*([^\r\n]+)\r\n", re.I)
TARGET_UA = b"Mozilla/5.0"          # 12 字节，与路由器方案一致

def mask_user_agent(packet) -> bool:
    """
    在 TCP payload 里原地替换 User-Agent。

    与 ua2f 的限制完全一致：
      · 新 UA 比原 UA 短 → 用空格填充（HTTP 规范会 trim）
      · 新 UA 比原 UA 长 → 截断（无法改变包长度）

    返回 True 表示改过。
    """
    payload = bytes(packet.payload)
    m = UA_PATTERN.search(payload)
    if not m:
        return False

    old = m.group(1)
    if len(TARGET_UA) > len(old):
        # 新 UA 太长，只能截断（与 ua2f 行为一致）
        new = TARGET_UA[:len(old)]
    else:
        new = TARGET_UA + b" " * (len(old) - len(TARGET_UA))

    packet.payload = payload[:m.start(1)] + new + payload[m.end(1):]
    return True
```

**关键限制**（必须写进文档，避免误解）：

1. **只能处理 HTTP（80 端口）**，HTTPS 的 UA 在 TLS 加密层里，改不了
2. **不能改变包长度**，所以新 UA 必须 ≤ 原 UA 长度
3. **只处理新建连接的首个请求**最有效；后续请求如果走同一个 TCP 连接，WinDivert 仍能看到（因为是明文）

#### 4.2.2 整合成统一开关

现有 `hotspot.py` 只管 TTL。建议扩成一个 `AntiDetect` 模块：

```python
# core/antidetect.py（新文件，或扩展现有 hotspot.py）

@dataclass
class AntiDetectConfig:
    ttl_fix: bool = True          # TTL 修复（现有）
    ua_mask: bool = False         # UA 归一（新增，默认关）
    target_ua: str = "Mozilla/5.0"
    ttl_target: int = 64


class AntiDetectEngine:
    """
    统一的防检测引擎。

    在 hotspot.py 的 TTL 过滤器基础上，增加 UA 改写。
    共用同一个 WinDivert handle，避免开两个驱动实例。
    """
    def __init__(self, cfg: AntiDetectConfig):
        self.cfg = cfg
        self._handle = None
        self._thread = None
        self._stop = threading.Event()
        self.stats = {"ttl_in": 0, "ttl_out": 0, "ua_masked": 0}

    def start(self):
        import pydivert
        filters = []
        if self.cfg.ttl_fix:
            filters.append(FILTER_INBOUND)
            filters.append(FILTER_OUTBOUND)
        if self.cfg.ua_mask:
            filters.append("outbound and tcp and tcp.DstPort == 80")

        self._handle = pydivert.WinDivert(" or ".join(f"({f})" for f in filters))
        self._handle.open()
        self._thread = threading.Thread(target=self._loop, daemon=True)
        self._thread.start()

    def _loop(self):
        while not self._stop.is_set():
            try:
                packet = self._handle.recv()
            except Exception:
                break

            changed = False

            # TTL
            if self.cfg.ttl_fix:
                if packet.direction == Direction.INBOUND and packet.ip.ttl <= 1:
                    packet.ip.ttl = self.cfg.ttl_target
                    self.stats["ttl_in"] += 1
                    changed = True
                elif packet.direction == Direction.OUTBOUND and packet.ip.ttl in (63, 127):
                    packet.ip.ttl = self.cfg.ttl_target
                    self.stats["ttl_out"] += 1
                    changed = True

            # UA
            if self.cfg.ua_mask and packet.tcp and packet.tcp.dst_port == 80:
                if mask_user_agent(packet):
                    self.stats["ua_masked"] += 1
                    changed = True

            self._handle.send(packet)
```

### 4.3 与路由器方案的关系

**两套方案是互补的，不是替代**：

| 场景 | 路由器方案 | Windows 侧 |
|---|---|---|
| 有线接校园网，路由器拨号 | ✅ TTL + ua2f | ❌ 不适用 |
| Windows 开热点共享 | ⚠️ 只能管自己的流量 | ✅ TTL + UA |
| 手机直连校园网 | ❌ | ❌ |

**推荐部署**：
- 长期用 → 路由器方案（M2 旁路由 + Cudy TTL，本次已落地）
- 临时/移动 → Windows 侧（hotspot.py 的 TTL + 新增 UA）

**不要同时开两套**：双层改写会产生 `TTL 64 → 63 → 64` 的抖动，虽然结果正确但浪费 CPU。

| 风险 | 说明 | 缓解 | 状态 |

| **HTTPS 的 UA 改不了** | TLS 加密层 | 如实告知，不承诺 | ⬜ 待实现 |

| **`extract_message_from_html` 过度抓取** | 原实现兜底返回前 120 字符，把 `<title>` 当报错 | 已修：只返回紧邻关键词的片段，无命中返回空串 | ✅ 已修 |

### 本次踩的坑（写进规范）

**坑：`extract_message()` 吃 `Response` 不吃 `str`**

原本只在 `submit()` 之后调用，拿的是 `resp`。注销判定拿到的是已经读出来的
HTML 字符串，直接传进去会 `AttributeError: 'str' object has no attribute 'text'`。

修法：抽出 `extract_message_from_html(html)`，`extract_message(resp)` 变成它的
薄封装（只做 `resp.text`）。两个入口共用核心逻辑，行为一致。

**坑：兜底逻辑「返回前 N 字符」对注销页是灾难**

原实现关键词全不命中时返回 `text[:120]` —— 对注销页那是
`断开网络 - 多运营商接入管理平台统一认证系统...`，
日志里每次都是这段噪音，根本看不出"有问题"和"没问题"的区别。

修法：先剔掉 `<head>/<script>/<style>/<title>`，再扫关键词，
一个都没命中就返回**空串**。

**坑：正则没考虑换行和可选标签**

`<span id="MainContent_LabelOnline" style="...">` 换行后才是
`<font color="...">未联网</font>`。原正则 `(?:<font[^>]*>)?\s*` 匹配不到
跨行的情况，实测页面解析出空串。

修法：`[\s\S]{0,120}?` 允许跨行，再捕获 `[已未]联网`。放宽了但更稳。
