## 一、项目是什么

**CampusLink** 是桂林信息科技学院（GUIT）校园网（`10.6.6.6` 门户）的自动认证工具，
解决的核心问题：门户验证码是**算术表达式**（如 `6乘12=?`，要求填计算结果 72），
抗 OCR 设计（随机颜色/倾斜/干扰线），传统识别只有 13% 正确率。

本项目训练了**专用 CRNN+CTC 模型**，在独立测试集上答案正确率 **92.2%**。

有两条产品线：

| 产品 | 形态 | 位置 | 用户 |
|---|---|---|---|
| **CampusLink**（GUI） | 托盘常驻，Qt 界面，断线自动重连，可选校园网共享 | 主仓库 `main` 分支，`CampusLink/` 文件夹 | 自己日常用 |
| **CampusLinkCLI**（无人值守） | 控制台一次性认证，装完即忘 | `cli-headless` 分支，`CampusLink-CLI/` 文件夹（git worktree） | 分发给同学/朋友 |

仓库：`https://github.com/aajj1314/CampusLink`（私有）

## 四、关键设计决策（别轻易改）

| 决策 | 原因 |
|---|---|
| 验证码识别用**专用 ONNX 模型**，不用通用 OCR | 该验证码抗 OCR（实测 ddddocr 仅 13%） |
| 识别置信度 <0.90 或算式除不尽 → **换图重试**（最多 8 次） | 错误识别会消耗一次登录尝试；实测错误是"看不见字边界"而非"不确定"，阈值救不回来，只能换图 |
| `is_online` 用 **gstatic + msftconnecttest 双点并行**，两点都过才算在线 | 校园网普遍放行 gstatic（防反复弹认证窗），单点会误判"已联网"跳过认证 |
| 网络判据用 **HTTP 响应内容**，不用 TCP 连通性 | 强制门户会劫持 :80 并代答 SYN，TCP 总是"通" |
| GUI 密码存 **Windows 凭据管理器**（keyring）；CLI 密码**明文 json**（用户拍板，单机自用） | CLI 的目标是"装完即忘"，不能弹凭据框 |
| CLI 打包 **console=True + vbs 静默包装** | 手动模式要控制台；开机静默用 `silent_run.vbs` 的 `Run ..., 0` 隐藏窗口。⚠️ **不要**改回 windowed+AllocConsole（标准流重定向在 windowed 下是坑窝，已实际踩崩两次） |
| 共享功能 TTL 过滤：`inbound TTL<=1 → 64`、`outbound 63/127 → 64` | 校园网出口代理回 SYN-ACK 时 TTL=1，Windows 转发递减到 0 丢弃；出站归一防私接检测。参数为线上验证值，**不要改** |

## 五、已知 Bug（用户 2026-11-18 实测反馈）

### 5.1 ⚠️ 界面持续"一闪一闪"：不断弹终端黑窗（已修，待验证）

- **现象**：装 11:41 版后，程序运行中不断有黑色控制台窗口一闪而过；
  进入软件后界面卡死
- **根因**：
  1. GUI 打包为 windowed（无控制台），但 `hotspot.local_ipv4_all()` /
     `netdetect.local_ipv4_all()` / `default_gateways()` 里调用 `subprocess.run(["ipconfig"])`、
     `["route", "print"]` 时**没有加 `CREATE_NO_WINDOW`** —— Windows 会给控制台子程序
     分配新控制台窗口，于是每次调用就弹一个黑窗
  2. 共享状态每 **3 秒**轮询一次（QTimer），即每 3 秒闪一次
  3. 同一轮询跑在 **UI 主线程**上（`ipconfig` 耗时 0.1~1s），界面被反复阻塞 → 卡死
- **修复**（2026-11-18）：
  - 新增 `core/proc.py::run_quiet()`，统一带 `CREATE_NO_WINDOW`
  - `hotspot`/`netdetect` 全部改用 `run_quiet`
  - GUI 共享状态改为**后台线程采集 + Signal 回主线程**（`_hotspotStatusReady`）
- **教训（写进规范）**：windowed 程序里**任何** `subprocess.run` 都必须带
  `creationflags=CREATE_NO_WINDOW`；**任何**耗时 IO 不能跑在 UI 线程

### 5.2 GUI 启动慢（用户反馈，未优化）

- 首次启动 1~3 秒：onedir 打包需加载 250+ DLL，且新装文件被杀软逐个扫描
- 优化方向：启动预热（GUI 版已用 WarmupWorker 预热 ONNX，实测有效）、
  减少 import 面、可选 UPX（注意杀软误报）

### 5.3 CLI 启动与联网检测慢（用户反馈，已部分优化）

- `is_online` 双点并行后最坏约 5 秒（单点 timeout）；进一步可把 timeout 降到 3s
- 启动 1~2 秒为 onedir 正常水平

### 5.4 CLI 首次配置交互无法自动化验证

- console 程序的 stdin 是 CONIN$（键盘），bash 管道喂不进去；
  首配逻辑由单测覆盖（mock stdin），exe 层验证到「黑窗弹出+提示词」为止

### 5.5 门户侧账号状态（非程序 bug）

- 门户对未实名账号回「账号未实名注册，请带证件到信息中心办理」，
  程序按关键词提前退出（不浪费重试次数）。这是**账号状态**问题，不是代码问题

### 6.2 构建命令（GUI）

```bash
python -m PyInstaller packaging/CampusLink.spec --noconfirm --clean \
       --distpath distN --workpath buildN
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" packaging/CampusLink.iss
```

### 6.3 ⚠️ 构建三大坑（都实际踩过）

1. **产物目录删不掉 → PyInstaller exit=1 → ISCC 照打旧包**
   环境有 SAFE_DELETE 策略（大量文件删除需确认/走回收站，CLI 目录下常失败）。
   **判断构建成功必须看产物时间戳/字节数变化**，不能只看 exit code。
   → 每轮构建换新 dist 路径（dist/dist2/.../dist6），并把 iss 的 `DistDir` 一起改。
2. **iss 的 `DistDir` 与实际构建路径不一致 → 安装包装的是旧版本**
   曾因 `sed 's/dist-cli2/.../'` 从未匹配到 `dist-cli`，导致 output 里所有安装包
   装的都是 15:21 的崩溃版（用户重装 N 次全部无效）。
   → **每次出包前 `grep DistDir packaging/*.iss` 核对路径**。
3. **PyInstaller 产物里的 DLL/驱动**：onnxruntime、keyring、pydivert 必须
   `collect_all`；WinDivert64.dll/.sys 缺了共享功能会报「pydivert 不可用」。
   → 构建后 `find distN -iname "*windivert*"` 验证。

## 九、给接手者的三条提醒

1. **先跑测试再改代码**：`pytest tests/ -q`，全绿基线是 300 条
2. **UI 线程不碰 IO**；windowed 子进程必带 `CREATE_NO_WINDOW`
3. **出包后核对三件事**：iss 的 DistDir 路径、产物时间戳变化、安装包内 exe 的 md5
   与 dist 目录一致（`md5sum` 对比）
